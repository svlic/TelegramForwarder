## 📖 简介

**当前版本: v1.7.2**

Telegram 转发器是一个消息转发与内容处理工具。只要你的用户账号已加入源频道/群组，就可以把指定聊天中的消息转发到目标聊天；Bot 不需要加入源频道/群组即可监听。项目适合信息流整合过滤、消息提醒、内容收藏、频道内容整理等场景，并可绕过 Telegram 的禁止转发/复制限制。

## ✨ 特性

- 🔄 **多源转发**：支持多个源聊天转发到同一个目标，也支持绑定时指定目标聊天
- 🔍 **关键词过滤**：支持黑名单、白名单、先黑后白、先白后黑，并支持正则关键词
- 📝 **内容替换**：支持正则替换、删除匹配内容、批量复制和导入导出替换规则
- 🤖 **AI 处理**：支持 OpenAI 兼容接口、模型选择、图片上传、AI 后二次关键词过滤
- 📊 **AI 总结**：支持定时总结、立即总结、自定义总结提示词和总结消息置顶
- 📹 **媒体过滤**：支持按媒体类型、大小、扩展名、caption 过滤，并可选择放行文本
- ⏱️ **延迟处理**：适用于频繁编辑消息的频道/群组，会延迟后重新获取消息内容
- ✏️ **编辑模式**：支持直接编辑原消息，也支持普通转发模式
- 🔗 **评论区直达**：原消息有评论区时可自动添加跳转按钮
- 🔁 **规则同步**：支持把当前规则的设置、关键词和替换规则同步到其他规则
- 🔗 **消息链接转发**：向 Bot 私聊发送 Telegram 消息链接即可复制转发原消息

## 🚀 快速开始

### 1️⃣ 准备工作

1. 获取 Telegram API 凭据：
   - 访问 https://my.telegram.org/apps
   - 创建一个应用获取 `API_ID` 和 `API_HASH`

2. 获取机器人 Token：
   - 与 @BotFather 对话创建机器人
   - 获取机器人的 `BOT_TOKEN`

3. 获取用户 ID：
   - 与 @userinfobot 对话获取你的 `USER_ID`

### 2️⃣ 配置环境

新建文件夹：
```bash
mkdir ./TelegramForwarder && cd ./TelegramForwarder
```

下载仓库的 [**docker-compose.yml**](https://github.com/Heavrnl/TelegramForwarder/blob/main/docker-compose.yml) 到目录下。

接着下载或复制仓库的 **[.env.example](./.env.example)** 文件，填入必填项，然后重命名为 `.env`：
```bash
wget https://raw.githubusercontent.com/Heavrnl/TelegramForwarder/refs/heads/main/.env.example -O .env
```

`.env` 必填项：
```ini
API_ID=
API_HASH=
PHONE_NUMBER=
BOT_TOKEN=
USER_ID=
```

可选项：
```ini
# 管理员列表，留空默认 USER_ID，多个用逗号分隔
ADMINS=

# 数据库连接，留空使用 sqlite:///./db/forward.db
DATABASE_URL=

# 默认时区
DEFAULT_TIMEZONE=Asia/Shanghai

# AI 模型列表与 OpenAI 兼容接口
AI_MODELS=
CUSTOM_AI_API_KEY=
CUSTOM_AI_API_BASE=
```

### 3️⃣ 启动服务

首次运行需要登录用户账号：
```bash
docker compose run --rm telegram-forwarder
```

按提示完成 Telegram 账号登录验证后，按 `CTRL+C` 退出。

后台运行：
```bash
docker compose up -d
```

### 4️⃣ 更新

使用 docker compose 运行时不需要拉取仓库源码，除非你打算自己 build。直接在项目目录执行：
```bash
docker compose pull
docker compose up -d
```

## 📚 使用指南

### 🌟 基础使用示例

假设订阅了频道 "TG 新闻" (`https://t.me/tgnews`) 和 "TG 阅读" (`https://t.me/tgread`)，但想过滤掉一些不感兴趣的内容：

1. 创建一个 Telegram 群组/频道，例如 "My TG Filter"。
2. 将机器人添加到这个目标群组/频道，并设置为管理员。
3. 在目标群组/频道中发送命令绑定源聊天：
   ```bash
   /bind https://t.me/tgnews
   /bind "TG 阅读"
   ```
   也可以在其他聊天中直接指定目标聊天：
   ```bash
   /bind https://t.me/source_channel https://t.me/target_channel
   /bind -1001234567890 -1009876543210
   ```
4. 打开设置菜单：
   ```bash
   /settings
   ```
   选择要操作的源聊天规则，点击 **应用当前规则**，后续关键词和替换规则命令就会作用到这条规则。
5. 添加屏蔽关键词：
   ```bash
   /add 广告 推广 '这是 广告'
   ```
6. 如果转发格式有多余符号，可以添加替换规则：
   ```bash
   /replace \*\*
   ```
   这会删除消息中的所有 `**` 符号。

> 注意：普通增删改查命令只作用于当前应用的规则。要切换规则，可以使用 `/settings(/s)` 或 `/switch(/sw)`。如果想对当前目标聊天绑定的所有规则生效，可以使用 `/add_all(/aa)`、`/add_regex_all(/ara)`、`/replace_all(/ra)` 等命令。

### 🔧 特殊使用场景示例

#### 1. TG 频道的部分消息由于文字嵌入链接，点击会让你确认再跳转，例如 NodeSeek 的官方通知频道

频道的原始消息格式：
```markdown
[**贴子标题**](https://www.nodeseek.com/post-xxxx-1)
```

可以对通知频道的转发规则 **依次** 使用以下指令：
```plaintext
/replace \*\*
/replace \[(?:\[([^\]]+)\])?([^\]]+)\]\(([^)]+)\) [\1]\2\n(\3)
/replace \[\]\s*
```

最终所有转发的消息都会变成以下格式，这样直接点击链接就无需确认跳转：
```plaintext
贴子标题
(https://www.nodeseek.com/post-xxxx-1)
```

---

#### 2. 监听用户消息格式不美观，可优化消息显示方式

**依次** 使用以下指令：
```plaintext
/r ^(?=.) <blockquote>
/r (?<=.)(?=$) </blockquote>
```

然后设置消息格式为 **HTML**，这样监听用户消息时，消息格式会更美观：

![示例图片](./images/user_spy.png)

---

#### 3. 同步规则操作

在 **设置菜单** 中开启 **同步规则**，进入 **同步设置** 选择目标规则后，当前规则的可同步操作会同步到选定规则。

适用于以下场景：
- 需要同时维护多个目标规则
- 不想在当前窗口逐条处理规则
- 创建一条只用于同步的模板规则

如果当前规则仅用于同步而不需要实际生效，可以把 **是否启用规则** 设置为 **否**。

## 🛠️ 功能详解

### ⚡ 过滤流程

当前代码中的实际过滤顺序如下：

```text
消息进入
  ↓
初始化规则与上下文
  ↓
延迟处理（可选，延迟后重新获取消息）
  ↓
文本标准化（去除 0 宽字符、Unicode 归一化）
  ↓
关键词过滤（黑名单/白名单/组合模式）
  ↓
替换规则处理
  ↓
媒体过滤（类型/大小/扩展名/caption/放行文本）
  ↓
AI 处理（可选，支持图片上传与 AI 后二次关键词过滤）
  ↓
原始信息处理（发送者、时间、原始链接）
  ↓
评论区按钮处理
  ↓
编辑模式处理（可选）
  ↓
发送处理（转发模式）
  ↓
回复处理（媒体组评论区按钮）
```

![img](./images/flow_chart.png)

关键点：
- 延迟处理在关键词过滤前执行，适合源消息经常被编辑的频道。
- 文本标准化会在文本过滤前统一去除常见 0 宽字符，并执行 Unicode 归一化，减少通过字符变体绕过关键词或替换规则的情况。
- 替换规则在 AI 前执行；AI 处理后如果开启 **AI 处理后再次执行关键字过滤**，会再次走关键词判断。
- 编辑模式和转发模式互斥。编辑模式会尝试修改原消息，转发模式会发送到目标聊天。
- 媒体组会做去重处理，避免同一组消息被重复转发。

| 延迟处理 | 启用后按设定秒数等待并重新获取原消息，再进入后续过滤流程 |
| 延迟秒数 | 从配置文件提供的秒数列表中选择，默认 5 秒 |
| 同步规则 | 开启后把当前规则的操作同步到已选择的同步规则 |
| 同步设置 | 选择当前规则要同步到哪些目标规则 |

### 🤖 AI 功能

项目使用 OpenAI 兼容接口，可以用于：
- 自动翻译外语内容
- 定时总结群组或频道消息
- 智能过滤广告信息
- 自动为内容打标签
- 去重相似内容
- 对图片消息进行视觉模型处理

#### 配置

在 `.env` 文件中配置模型列表和 OpenAI 兼容接口：
```ini
# AI 模型列表，逗号分隔
AI_MODELS=gpt-4o,claude-3-sonnet,gemini-2.0-flash

# OpenAI 兼容接口
CUSTOM_AI_API_KEY=your_key
CUSTOM_AI_API_BASE=https://your-api-endpoint.com/v1
```

> AI 模型通过 `AI_MODELS` 环境变量配置，在 AI 设置界面中选择。不同模型是否支持图片取决于你的接口服务。

#### AI 处理

AI 处理提示词中可以使用以下占位符读取上下文：
- `{source_message_context:数字}`：获取源聊天最新的指定数量消息
- `{target_message_context:数字}`：获取目标聊天最新的指定数量消息
- `{source_message_time:数字}`：获取源聊天最近指定分钟数的消息
- `{target_message_time:数字}`：获取目标聊天最近指定分钟数的消息

提示词示例：

前置：开启 **AI处理后再次执行关键字过滤**，并把 `#不转发` 添加到过滤关键词中。

```text
这是一个资讯整合频道，从多个源获取消息，现在你要判断新资讯是否和历史资讯内容重复了，若重复，则只需要回复“#不转发”，否则请返回新资讯的原文并保持格式。
记住，你只能返回“#不转发”或者新资讯的原文。
以下是历史资讯：{target_message_context:10}
以下是新资讯：
```

#### 定时总结

开启定时总结后，机器人会在指定时间自动总结当前规则对应聊天中过去一段时间的消息。

可配置项：
- 总结时间：从 `config/summary_times.txt` 候选项中选择
- 默认时区：通过 `.env` 的 `DEFAULT_TIMEZONE` 设置
- 总结提示词：在 AI 设置菜单中配置
- 顶置总结消息：开启后会尝试置顶总结结果
- 立即执行总结：用于手动触发一次总结

> 注意：总结和图片上传会消耗较多 API 额度，请根据需要开启。

## 🎯 特殊功能

### 🔗 链接转发功能

向 Bot 私聊发送 Telegram 消息链接，即可把那条消息复制转发到当前私聊窗口。支持公开频道链接和私有频道 `t.me/c/...` 链接，用户账号必须有权限访问原消息。

支持内容：
- 纯文本消息
- 单条媒体消息
- 媒体组消息
- 原消息按钮
- caption

示例：
```text
https://t.me/channel_name/123
https://t.me/c/123456789/123
```

注意：链接转发只在给 Bot 的私聊中触发；如果无法访问频道、消息已删除或链接错误，会返回提示。

## 📝 命令列表

```bash
命令列表

基础命令
/start - 开始使用
/help(/h) - 显示帮助信息
/changelog(/cl) - 查看更新日志

绑定和设置
/bind(/b) <源聊天链接或名称或ID> [目标聊天链接或名称或ID] - 绑定源聊天，可指定目标聊天
/settings(/s) [规则ID] - 管理转发规则
/switch(/sw) - 切换当前管理的规则

转发规则管理
/list_rule(/lr) - 列出所有转发规则
/delete_rule(/dr) <规则ID> [规则ID] [规则ID] ... - 删除指定规则
/copy_rule(/cr) <源规则ID> [目标规则ID] - 复制指定规则的所有设置到当前规则或目标规则

关键字管理
/add(/a) <关键字> [关键字] ["关 键 字"] ['关 键 字'] ... - 添加普通关键字
/add_regex(/ar) <正则表达式> [正则表达式] [正则表达式] ... - 添加正则关键字
/add_all(/aa) <关键字> [关键字] [关键字] ... - 添加普通关键字到当前目标聊天绑定的所有规则
/add_regex_all(/ara) <正则表达式> [正则表达式] ... - 添加正则关键字到当前目标聊天绑定的所有规则
/list_keyword(/lk) - 列出当前规则的关键字
/remove_keyword(/rk) <关键词> ["关 键 字"] ['关 键 字'] ... - 删除普通关键字
/remove_keyword_by_id(/rkbi) <ID> [ID] [ID] ... - 按 ID 删除关键字
/remove_all_keyword(/rak) <关键词> ["关 键 字"] ['关 键 字'] ... - 删除当前目标聊天所有规则中的指定关键字
/clear_all_keywords(/cak) - 清除当前规则的所有普通关键字
/clear_all_keywords_regex(/cakr) - 清除当前规则的所有正则关键字
/copy_keywords(/ck) <规则ID> - 复制指定规则的普通关键字到当前规则
/copy_keywords_regex(/ckr) <规则ID> - 复制指定规则的正则关键字到当前规则

替换规则管理
/replace(/r) <正则表达式> [替换内容] - 添加替换规则；不填替换内容表示删除匹配内容
/replace_all(/ra) <正则表达式> [替换内容] - 添加替换规则到当前目标聊天绑定的所有规则
/list_replace(/lrp) - 列出当前规则的替换规则
/remove_replace(/rr) <序号> - 删除替换规则
/clear_all_replace(/car) - 清除当前规则的所有替换规则
/copy_replace(/crp) <规则ID> - 复制指定规则的替换规则到当前规则

导入导出
/export_keyword(/ek) - 导出当前规则的关键字
/export_replace(/er) - 导出当前规则的替换规则
/import_keyword(/ik) <同时发送文件> - 导入普通关键字
/import_regex_keyword(/irk) <同时发送文件> - 导入正则关键字
/import_replace(/ir) <同时发送文件> - 导入替换规则

危险命令
/clear_all(/ca) - 清空所有聊天、规则、关键字和替换规则；需要输入确认文本

提示
• 括号内为命令的简写形式
• 尖括号 <> 表示必填参数
• 方括号 [] 表示可选参数
• 导入命令需要同时发送文件
• 普通增删改查默认作用于当前应用的规则
```
